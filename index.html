python-constraint: an index-based search plan, real MRV, and scoped forward checking

01The problem in the original loop

The default solver, OptimizedBacktrackingSolver, is an iterative depth-first search. Every node runs this:

# pick the next variable
lst = [(-len(vconstraints[v]), len(domains[v]), v) for v in domains]
lst.sort(key=lambda x: (x[0], x[1]))
for item in lst:
    if item[-1] not in assignments:   # first unassigned in that order
        variable = item[-1]
        values = domains[variable][:]
        if forwardcheck:
            pushdomains = [domains[x] for x in domains
                           if x not in assignments and x != variable]
        break

Three things are wrong with those nine lines, and none of them is a style issue.

1 · rebuilt every node

The list of n tuples is rebuilt and re-sorted on every node — after each failed value, not just after each assignment. Everything in it except the domain sizes is static for the whole search.

2 · MRV is frozen

len(domains[v]) is the size at the root. Forward checking shrinks domains as the search descends, but the heuristic never reads them again — so “minimum remaining values” degrades into a static tie-breaker.

3 · pushing every domain

Assigning one variable pushes a state onto every unassigned domain, although a constraint can only hide values in the domains of its own variables. On a sparse constraint graph that is O(V) wasted work per assignment.

The consequence is measurable rather than theoretical: on 20-queens the upstream search performs 4,902,182 constraint invocations to find one solution, because it keeps walking a stale order while some other variable has already been pruned to a single value. On the classic hard sudoku it is 1,916,096.

02What was changed

All of the algorithmic work is in constraint/solvers.py. A SearchPlan is built once per solve (variable order, degrees, constraint-neighbour table, index map); the per-node heuristic becomes a single allocation-free scan over a taken bitmap that reads the live domain sizes; and forward checking only pushes the domains of the current variable’s constraint neighbours.

Both switches are on the constructor, so the old behaviour can be restored exactly:

OptimizedBacktrackingSolver(
    dynamic_mrv=False,
    restricted_pushdomains=False,
)  # == upstream 2.7.3
Why they stay separate. The ablation below shows the two changes are not interchangeable: dynamic MRV produces the orders of magnitude but is a net loss on pure enumeration, while the restricted push list is what pays exactly there. Wiring either one in unconditionally would have made some workloads slower.

Including the uncomfortable parts. Dynamic MRV is 0.83× on dedispersion and 0.93× on microhh — on pure enumeration it only costs time. 05Correctness

  • Upstream test suite: 76 passed, 1 skipped, 2 failed — and the same two fail on the untouched upstream checkout here (test_if_compiled expects a Cython build; test_versioning imports poetry).
  • 29 new tests: solution-set equality against the “both switches off” configuration on n-queens, sudoku, dedispersion, sparse graphs, unary constraints, non-string variable keys, unsatisfiable problems and repeated solves.
  • Every benchmark case asserts its solution count and aborts on a change, so a timing run can never compare two different searches.
  • The project’s own ruff configuration passes on the whole tree, including bench/.

A crash found on the way

ExactSumConstraint, MinSumConstraint and MaxSumConstraint computed their initial bounds with min(domains[v]) without checking for an empty domain. preProcess runs on every solve and its pruning is never undone, so solving the same Problem twice raised ValueError: min() iterable argument is empty on the second call. Fixed with the same guard the recalculation a few lines below each site already used, plus three regression tests.

06Limitations

  • Pure Python only. The Cython .c artifacts were removed (generated, and no longer matching the modified sources); the relative gain would shrink in a compiled build, since the Python-level overhead removed here is what Cython already removes.
  • No memory measurement was taken, so no memory claim is made.
  • ParallelSolver and MinConflictsSolver are untouched — the first is documented upstream as experimental, the second is local search without forward checking, where these changes do not apply.
  • The first solution found may differ from upstream when dynamic MRV is on. The solution is still valid and the solution set is identical.
